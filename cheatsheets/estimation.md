# Оценки на салфетке

Числа, которые надо помнить, чтобы за две минуты прикинуть нагрузку и объём. Все значения это **порядки величин**: на интервью важен вывод («одна БД справится» или «нужны шарды»), а не третья цифра.

[← все шпаргалки](README.md)

## Рецепт оценки
1. **Пользователи:** DAU и сколько действий делает один в день.
2. **Средний QPS:** действий в день ÷ 10⁵.
3. **Пик:** ×2–5 от среднего (в книге обычно ×5).
4. **Объём за день:** записей в день × размер записи.
5. **Объём за срок хранения:** × 365 × лет × число копий.
6. **Трафик:** QPS × размер ответа.
7. **Вывод:** что из этого следует для архитектуры. Без вывода оценка бесполезна.

## Время
| Сколько | Секунд | Запомнить как |
|---|---|---|
| День | 86 400 | ≈ 10⁵ |
| Месяц | 2,6 млн | ≈ 2,5 × 10⁶ |
| Год | 31,5 млн | ≈ 3 × 10⁷ |

| В день | В секунду |
|---|---|
| 1 млн | ≈ 12 |
| 100 млн | ≈ 1 200 |
| 1 млрд | ≈ 12 000 |

Деление на 10⁵ вместо 86 400 занижает на 15%: для оценки годится.

## Степени двойки
| Степень | Примерно | Единица |
|---|---|---|
| 2¹⁰ | тысяча | КБ |
| 2²⁰ | миллион | МБ |
| 2³⁰ | миллиард | ГБ |
| 2⁴⁰ | триллион | ТБ |
| 2⁵⁰ | 10¹⁵ | ПБ |

Удобно считать так: 1 млн записей по 1 КБ = 1 ГБ; 1 млрд записей по 1 КБ = 1 ТБ.

## Сколько что весит
| Что | Размер |
|---|---|
| int64, timestamp | 8 Б |
| UUID | 16 Б (36 символов строкой) |
| Строка таблицы с десятком полей | 100 Б – 1 КБ |
| Короткий текст, пост | сотни байт |
| Письмо с заголовками | десятки КБ |

## Задержки
| Операция | Время |
|---|---|
| Обращение к кэшу процессора L1 | ~1 нс |
| Обращение к оперативной памяти | ~100 нс |
| Сжать 1 КБ | несколько мкс |
| Случайное чтение с SSD | десятки–сотни мкс |
| Прочитать 1 МБ из памяти подряд | десятки–сотни мкс |
| Запрос внутри одного дата-центра туда и обратно | ~0,5 мс |
| Прочитать 1 МБ с SSD подряд | ~1 мс |
| Позиционирование головки HDD | ~10 мс |
| Запрос между континентами туда и обратно | ~150 мс |

**Что из этого следует:**
- Память быстрее диска на порядки, поэтому горячее держат в памяти (главы 1, 2, 10, 13).
- Диск быстр, когда читают и пишут подряд, и медленен на случайном доступе. На этом стоят лог Kafka (глава 4) и склейка объектов (глава 9).
- Сеть внутри дата-центра стоит полмиллисекунды. Для биржи это слишком много (глава 13), для остальных глав незаметно.
- Между континентами 150 мс. Синхронная репликация через океан делает каждую запись медленной: [несколько регионов](multi-region.md).

## Что держит одна машина
Грубые ориентиры, сильно зависят от запроса и железа.

| Компонент | Порядок |
|---|---|
| Stateless-сервис с простой логикой | тысячи запросов в секунду |
| Реляционная БД, запись | тысячи в секунду |
| Реляционная БД, простое чтение по ключу | десятки тысяч в секунду |
| Redis | ~100 тыс. операций в секунду |
| Партиция Kafka | десятки МБ в секунду |
| WebSocket-соединений на сервер | сотни тысяч |
| HDD | 100–200 IOPS |
| SSD | десятки и сотни тысяч IOPS |
| Сеть 1 Гбит/с | 125 МБ/с |
| Сеть 10 Гбит/с | 1,25 ГБ/с |

## Доступность
| Девятки | Простой в год | Простой в месяц |
|---|---|---|
| 99% | 3,65 дня | 7,3 часа |
| 99,9% | 8,8 часа | 44 минуты |
| 99,99% | 53 минуты | 4,4 минуты |
| 99,999% | 5,3 минуты | 26 секунд |

- **Последовательно** (запрос проходит через оба): доступности перемножаются. Два сервиса по 99,9% дают 99,8%.
- **Параллельно** (хватит любого): 1 − (1 − a)ⁿ. Две копии по 99% дают 99,99%, но только если отказы независимы (глава 9: домены отказа).

## Частые ошибки
- Посчитать и не сделать вывод.
- Забыть пик: система падает не на среднем.
- Забыть копии и срок хранения: объём за день выглядит маленьким.
- Считать, что чтение и запись одинаковы: почти везде чтений в 10–100 раз больше.
- Тратить на арифметику больше пяти минут.
